# Граф новостей: памятка команды

## Что хранится и что видно

Producer сохраняет материалы, claims и результаты обработки в Vault JSON. Расширение
читает эти артефакты, удерживает ревизии и точные цитаты в SQLite, добавляет журнал
решений и собирает статический viewer. Просмотр не запускает extraction или модель.

Граф состоит из узлов и направленных рёбер. В режиме источников видны материалы
и их происхождение; в режиме утверждений видны claims и интерпретации их отношений.
Тема и история помогают ориентироваться, но сами не являются доказательствами.

| Элемент | Как читать |
|---|---|
| Узел claim | Конкретное утверждение конкретной ревизии. Откройте сохранённую цитату. |
| Ребро | Выбирайте саму стрелку: у одной пары могут быть разные решения, направления и условия. |
| SUPPORTS / CONTRADICTS | Оценка поддержки или противоречия при указанных условиях, не независимая проверка истины. |
| CORRECTS / SUPERSEDES | Исправление или замещение в сохранённом направлении. Они не переключают выбранную ревизию автоматически. |
| DUPLICATES / ELABORATES | Дублирование или уточнение. Не превращайте перепечатки в независимые подтверждения. |
| MODEL_ASSESSED / review | Оценка модели и решение оператора имеют разное происхождение. Наличие ребра не означает одобрения. |

Положение и близость узлов нужны для чтения карты. Они не показывают достоверность,
причинность или силу доказательства. На canvas помещаются до 20 основных узлов и
60 рёбер страницы. Используйте фильтры и текстовый список, чтобы открыть остальные.

## Рабочий цикл

1. Импортируйте неподвижный producer snapshot. Новая ревизия сохраняется рядом со
   старой; она не получает её review. При необходимости явно выберите ревизию.
2. Откройте тему, историю и нужную стрелку. Сравните обе цитаты, даты, версии,
   датасет и условия. Два выбранных узла без выбранного ребра дают нейтральное сравнение.
3. Для review сначала получите текущее состояние и token через `review show`.
   Решение записывается вместе с обоснованием. При stale-token перечитайте evidence.
4. После смены ревизии или отзыва предпосылки старое решение остаётся в истории,
   но может перестать действовать. Возврат к прежней ревизии восстанавливает
   применимость при остальных прежних условиях, однако старый token уже не подходит.
5. Для передачи наружу используйте `export-public` с явным allowlist полей, цитат
   и решений. Публичная история не раскрывает текущее private-состояние:
   `current_applicability=not_disclosed`. Скрытый отзыв не должен менять такой экспорт.

Быстрый запуск без inference из корня checkout:

```bash
demo_dir="$HOME/newsmap-demo-$(date +%Y%m%d-%H%M%S)"
python3 extensions/news_graph/run.py demo "$demo_dir"
python3 -m http.server 8765 --bind 127.0.0.1 --directory "$demo_dir/viewer"
```

Откройте `http://127.0.0.1:8765/`. Demo синтетическое. Команды review, импорта и
экспорта описаны в [README](README.md); параметры доступны через `run.py --help`.
На MacBook используйте локальный APFS вне iCloud. Нативная проверка Mac/Safari ещё впереди.

## Зачем здесь Lean

Lean 4 позволяет записать состояние, переход и утверждение о нём, затем проверить
доказательство ядром языка. `structure` задаёт поля состояния, `def` функцию,
`theorem` утверждение, а `by` начинает доказательство. Например, из нашей модели:

```lean
theorem stale_review_noop (s : NewsState) (old : Nat) (r : Review) (h : old ≠ s.token) :
    reviewCommand s old r = s := by simp [reviewCommand, h]
```

Здесь `h` является условием: token устарел. Вывод: состояние не изменилось.
`simp` раскрывает определение перехода и упрощает выражение с учётом условия.
В Python такой отказ выражен исключением и отсутствием записи в журнале.

В [NewsGraph.lean](proofs/NewsGraph.lean) проверяются привязка к ревизиям, review,
сохранение истории, точная цитата по Unicode code points, границы страницы, концы
ребра, выбор его контекста и разрешённая публичная история. В
[SelectionBudget.lean](proofs/SelectionBudget.lean) проверяются выбор и учёт перерасхода.
Это **38 теорем о модели**, а не доказательство правдивости новостей или всего приложения.
Условия соответствия перечислены в [PROOF_TRACE_RU.md](PROOF_TRACE_RU.md).

Проверка использует уже установленный **Lean 4.8.0**, без Mathlib и загрузок:

```bash
python3 extensions/news_graph/proofs/check.py --lean /absolute/path/to/lean
```

Скрипт компилирует оба файла, проверяет вывод `#print axioms` и отсутствие `sorry`.
Стандартные `propext`, `Classical.choice`, `Quot.sound` допустимы; собственных аксиом
нет. `#eval` с общим JSON-сценарием является исполняемым примером, а не новой теоремой.

В окружении с pytest, Playwright и Chrome соответствие коду проверяется так:

```bash
PYTHON_DOTENV_DISABLED=1 PYTHONPATH=.:extensions/news_graph/src python -m pytest -q \
  extensions/news_graph/tests/test_formal_trace.py
```

Браузерный fixture сейчас ожидает Linux Chrome в `/usr/bin/google-chrome` и отключает
GPU. Lean-команда не зависит от этого браузера; browser-тест не подтверждает macOS.

## Как проверять изменения другими моделями

Зафиксируйте исходники и их хеши. Передайте рецензенту небольшой контракт, связанные
функции и контрпримеры без секретов и частных данных. Просите искать неверные условия
и расхождения с кодом. После ответа воспроизведите замечание, внесите минимальную
правку, заново скомпилируйте Lean и прогоните соответствующий тест. Согласие моделей
не заменяет этих шагов.

Новую модель `NewsGraph.lean` проверяли Cursor Agent с настроенным Grok 4.7 Extra High и agy с Argon
Medium. По замечаниям уточнены gates evidence, правая сторона связи, история review,
пагинация и публичная closure. Предположение о восстановлении старого token отклонено
по коду и тесту: новое событие выбора меняет `head_token`. Предложение учитывать
скрытый отзыв в публичной истории отклонено как нарушение её контракта приватности.

Для изучения языка: [Theorem Proving in Lean 4](https://lean-lang.org/theorem_proving_in_lean4/)
и [аксиомы и вычисления](https://lean-lang.org/theorem_proving_in_lean4/Axioms-and-Computation/).
Онлайн-книга обновляется; воспроизводимость этого checkpoint привязана к 4.8.0.
